PRD — Mini Clip Editor (V1)
Feature

Mini editor liviano para ajustar clips generados automáticamente por IA.

El usuario podrá:

modificar inicio y final del clip,
previsualizar cambios,
y exportar nuevamente el clip corregido.

La feature NO busca competir con editores profesionales.

Objetivo:
permitir micro-ajustes rápidos que aumenten calidad percibida y reduzcan frustración.

Objetivo del producto

Resolver problemas típicos del clipping automático:

hook empieza tarde,
punchline queda cortado,
sobra silencio,
falta contexto,
corte se siente abrupto.

La IA genera el 90%.
El usuario corrige el 10%.

Objetivos de negocio
Primarios
aumentar satisfacción con clips generados,
aumentar tasa de exportación,
reducir abandono por clips “casi buenos”,
mejorar percepción de calidad de IA.
Secundarios
aumentar retención,
disminuir requests de soporte,
diferenciar producto frente a competitors más rígidos.

Story 2

para evitar que el remate quede cortado.

Story 3

Como usuario,
quiero ver el preview inmediatamente,
para validar si el clip quedó bien.

Story 4

quiero exportar una nueva versión,
para publicar el clip corregido.

Arquitectura técnica
Frontend

Responsabilidades:

render preview,
timeline UI,
manejo de timestamps,
reproducción local.

NO renderiza video final.

Backend

Responsabilidades:

recibir nuevos timestamps,
cortar nuevo segmento,
reprocesar subtitles,
exportar nuevo clip.
Flujo técnico
1. Usuario abre clip

Frontend recibe:

{
  "clip_id": "clip_01",
  "video_url": "...",
  "start": 1320,
  "end": 1360
}
2. Usuario ajusta timestamps

Frontend actualiza estado local:

{
  "new_start": 1315,
  "new_end": 1365
}
3. Preview local

HTML5 video:

usa seek,
reproduce rango simulado.
4. Usuario guarda

POST:

{
  "clip_id": "clip_01",
  "start": 1315,
  "end": 1365
}
5. Backend crea render job

Nuevo estado:

rendering_adjusted_clip
6. Worker ejecuta ffmpeg

Ejemplo:

ffmpeg -ss START -to END -i input.mp4 \
-c:v libx264 \
-c:a aac \
output.mp4
7. Se genera nuevo asset

Guardar:

nuevo mp4,
nueva preview,
nuevos subtitles.

Decisiones importantes
Decisión 1

NO renderizar en browser.

Motivo:

performance,
compatibilidad,
simplicidad.
Decisión 2

NO construir editor completo.

Motivo:

distrae del core product,
aumenta muchísimo complejidad.
Decisión 3

El editor existe para:

corregir,
no para crear desde cero.
Definición de éxito

La feature es exitosa si:

el usuario puede corregir un clip en menos de 30 segundos,
el flujo se siente instantáneo,
y aumenta la cantidad de clips exportados/publicados.
